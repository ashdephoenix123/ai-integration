***Basic Concepts***
1. What is the difference between a token and a word?
Tokens are units of text the model processes.

2. What is a context window, and what happens when the conversation exceeds it?
a model's memory, when conversation exceeds, the old token are deleted.

3. Why do LLMs use tokens instead of words?
If the model stored every possible word, the vocabulary would become enormous. so saving units of text helps model to -
- Handle unseen words.
- Work across many languages.
- Keep a manageable vocabulary (~50k–200k tokens instead of millions of words).
- Break words into reusable pieces.

***Transformers***
1. At a high level, what problem do transformers solve?
Transformers solve the problem of understanding relationships between words regardless of how far apart they are, and doing so efficiently.

2. What does "attention" mean in transformers?
When processing a token, the model assigns different importance (weights) to other tokens in the context.
For example: "The dog didn't cross the road because it was tired."
When processing "it", the model gives high attention to "dog" and low attention to "road". 
So attention = deciding which words are important for understanding the current word.

3. Why are transformers better than RNNs for long sequences?
RNNs read word by word, so the early tokens can weaken over long distances. 
Transformers - 
    . use attention to connect one token directly with another token regardless of how far each token is from each other.
    . process all tokens simultaneously.
For example:
"The car, which John bought after saving money for years, was expensive because it...". The model can directly connect "it" with "car".

***Embeddings & Vector Databases***
1. What is an embedding?
Embeddings are numerical representation of an information. They can represent words, sentences, paragraphs, images, etc.

2. Why can't we directly store embeddings in a normal SQL database and perform similarity search efficiently?
getting response for "give me the similar products like this one" might be wrong using normal sql dbs because thay are optimized for looking up exact matching. embeddings are vectors which have meaning and those numbers are represented in multi dimenion space so vector databases are optimized for that which gives proper result for queries like that.

3. Explain cosine similarity in simple terms.
if two vectors points to same direction then the match is equal. cosine similarity gives the cosine of the angle between two vector points in multi dimension space, the less the angle the closer are the vectors to each other.
Similar direction → cosine ≈ 1
Perpendicular → cosine ≈ 0
Opposite direction → cosine ≈ -1

4. What other similarity measures do you know besides cosine similarity?
1. Euclidean distance - distance between two vectors.
2. dot product - x1x2 + y1y2 + ...
3. Manhattan Distance |x1-x2| + |y1-y2| + ...

***RAG***
1. Describe the RAG pipeline from a user's query to the final answer.
User query
    ↓
Convert query into embedding
    ↓
Search vector database
    ↓
Retrieve relevant chunks
    ↓
Insert chunks into prompt
    ↓
Send augmented prompt to LLM
    ↓
LLM generates answer

Notice that the model itself doesn't say "I need information" in classical RAG. Your application performs retrieval before calling the model.

2. Why do we chunk documents before creating embeddings?
. Whole documents may exceed context limits.
. Smaller chunks give more precise retrieval.
. Embeddings represent smaller ideas better than huge documents

Suppose a 500-page PDF contains a page about refunds. If you embed the entire PDF, similarity search may not find that specific section well.

PDF
↓
Chunk 1
Chunk 2
Chunk 3
...
Chunk 500
↓
Embeddings
↓
Vector DB

Then only relevant chunks are retrieved.

3. Why don't we simply send an entire PDF to the LLM?
. Expensive token usage.
. Context window limits.
. Lots of irrelevant information.
. Lower answer quality due to distraction.

4. What's the difference between retrieval and generation in RAG?
retrieval -> getting inside information to be sent to model.
geenration -> the response generated by model using that retrieed information.

5. Why is RAG often preferred over fine-tuning for company knowledge bases?
RAG
✅ Easy to update
✅ No retraining
✅ Lower cost
✅ Data stays external
✅ Good for changing documents

Fine-tuning
✅ Changes behavior/style
❌ Expensive
❌ Must retrain for new data
❌ Bad for frequently changing knowledge
